# 侧栏切页位移排查

## 原因

侧栏选择状态没有错，变化的是整个 `NavigationSplitView` 的布局高度。
`PageHeader` 的说明文字使用了 `.fixedSize(horizontal: false, vertical: true)`。
分栏测量最小尺寸时，说明文字在很窄的宽度下大量换行，又要求保留完整高度，
使窗口不能容纳分栏，侧栏和详情一起越过窗口边界。

最小复现只保留原生分栏、一个菜单和 `PageHeader`，不需要切页、底部 inset、
搜索或工具栏。在 1080 × 700 的内容区域中，旧约束让分栏高度变成 1294pt，
侧栏起点为 -281pt。删除该约束后，分栏高度回到 700pt。

扩展检查发现另一个相同症状的入口：MCP 左侧直接排列全部配置，没有滚动容器。
隔离的 24 条配置让分栏高度达到约 1602pt。将这部分改为原生滚动列表后，
列表增长只增加滚动内容，不再增加窗口最小高度。

## 修复与验证

- 删除标题说明的纵向固定尺寸；撤掉上一轮根分栏的 `GeometryReader`。
- 为 MCP 配置列表使用 `ScrollView` 与 `LazyVStack`。
- 缩小 Skills 双栏的过大最小宽度，消除 1080pt 窗口下的横向越界。
- `swift test --filter NavigationLayoutTests` 承载两个真实原生布局测试：
  单独标题组件，以及三种窗口尺寸、八个页面正反向切换的 48 个页面状态。
- 集成测试隔离 Application Support 与宿主 HOME，使用 24 条本地 MCP 配置和
  24 个插件 manifest；检查侧栏位置不变、滚动区域不越界、长列表末尾可达。
- 修复前已经分别观察到标题最小复现失败、长 MCP 列表越界和 Skills 横向越界。
  Core 测试仅验证 Core 行为，不作为 UI 正确性的证据。
