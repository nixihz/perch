# 项目接入、配置落地与退出管理

状态：第一阶段已实现（2026-10-21）：本机归属收据、已有配置冲突、取消技能或宿主后的受管内容移除、恢复预检与项目技能现状。接入基线、恢复接入前状态、退出管理和完整操作历史界面仍待实现；下文保留这些目标设计。

## 1. 本轮范围与现状

把“打开已有项目 → 识别配置 → 选择能力 → 预览写入 → 使用 → 取消或还原”作为连续流程设计。首次接入不能假设项目为空；退出管理必须保留接入前的内容和之后的用户编辑。

“框架”暂按包含多项技能、规则、MCP 或插件的组合讨论，尚未确定专用格式。纯组合沿用 PresetRevision；涉及安装器、hooks 或宿主命令的部分按 Plugin 生命周期处理。若用户所指为其他类型，需要补充样例后再确定适配方式。

| 能力 | 当前代码事实 | 本提案补充 |
| --- | --- | --- |
| 项目盘点 | `ProjectInspector` 观察 Codex 与 Claude 项目目录，分别记录归属和内容状态；项目页、CLI/MCP 查询可见 | 继续补继承、规则加载链与完整扫描范围提示 |
| 已有技能 | 相同内容保留原归属；本机收据结合当前锁才能证明受管 | 明确接管已有内容的操作仍待实现 |
| 技能落地 | `DeploymentPlanner` 支持固定版本软链接和复制，拒绝覆盖同路径未受管的不同内容；受管漂移也阻塞 | 宿主实际加载仍需在宿主中确认 |
| 取消选择 | 为旧受管集合中取消的技能及宿主入口生成 remove 计划，不删除相邻外部技能 | 用户级继承还不能据此判定关闭 |
| 规则整合 | 跟踪块正文指纹；移除取消宿主或规则的受管块，保留块外编辑；未知归属的同标记块保留或报冲突 | 继续补自然语言规则冲突提示与真实加载验证 |
| 还原 | 移除操作有备份；撤销前预检已应用步骤；逐步保存恢复状态，支持删除与恢复临时路径的中断续办；保留原本存在的空规则文件 | 接入基线、完整退出管理、三方合并与更多故障注入仍待实现 |

本机收据保存在 operation journal，锁中的 `managementRevision` 区分实际部署批次，不携带机器路径。归属缺失时保留已有内容，不根据 catalog 指纹或锁自动接管。升级前不含归属收据及读取依赖的待执行部署计划须重新生成。行为覆盖见 `ProjectIntegrationTests`、CLI 集成测试及原生 UI 的 `@projectintegration` 场景。

## 2. 首次接入：先盘点，再决定整合方式

打开项目只读取文件并保存本机观察；不创建项目 manifest、不更改已有规则或技能。项目 realpath 去重，独立 worktree 分别管理。重新打开不得重设首次接入基线。

按已适配宿主盘点项目发现目录、规则文件、项目锁、MCP 配置和插件安装事实，并检查相关祖先、用户级规则和嵌套规则。嵌套检查要有文件数、深度与忽略范围限制；读取失败或超出范围显示“扫描不完整”。继承扫描不读取凭据，不写项目外路径；未支持的加载规则显示“有效状态未知”。

每条观察至少展示：宿主、作用域、来源路径、实体或链接、版本依据、管理归属、漂移情况和加载验证状态。以下维度分别记录，不能压成一个勾选值：

- 项目期望：用户希望启用什么。
- 实际观察：目前发现了什么；配置存在与宿主已加载分别显示。
- 管理归属：栖集受管、项目已有、其他工具管理、继承或未知。
- 冲突与漂移：同名不同内容、受管内容被改动、链接异常、规则遮蔽等。

整合动作：

| 情况 | 默认处理 | 可选动作 |
| --- | --- | --- |
| 已有技能与选中版本相同 | 显示“项目已有”，保留原管理归属 | 明确接管：记录原始状态与 ownership，预览元数据变更 |
| 同名技能内容不同或来源不明 | 阻塞同路径写入，展示差异 | 保留已有、取消新选择，或另行审阅替换计划；重命名仅在宿主支持时提供 |
| 已有目录或文件是软链接 | 记录链接文本与可解析状态；断链、循环和越界明确提示 | 保留原状；替换链接必须另列计划，不写链接目标 |
| 已有 `AGENTS.md` / `CLAUDE.md` | 保留原文；计划只追加栖集受管块 | 审阅规则差异；明确冲突交给用户选择 |
| 已有其他工具的规则标记 | 保留其归属和内容 | 不接管其标记；需要迁移时单独设计 |
| 已有有效项目 manifest 和锁 | 校验后恢复该项目的期望与锁定版本 | 本机没有历史备份时，提示无法恢复另一台机器的接入前状态 |
| manifest、锁或受管标记损坏 | 保留文件，阻塞相关写入 | 展示修复差异，不能当成空项目重建 |

规则冲突检查只给出有依据的提示，例如语言要求冲突、相反的操作约束；不承诺自动判定自然语言规则是否兼容。AI 可提出整合草稿，不能自动改写原有正文。按宿主版本解释优先级；未知、遮蔽和未验证状态必须可见。

## 3. 选择、存储与落地方式

勾选是编辑项目草稿的交互；复制、软链接和宿主引用是实际落地方式，两者分开。项目页的默认流程为“点击工具图标选择 → 预览变更 → 保存当前计划 → 写入并回读 → 宿主加载验证”。保存按钮就是对所审阅 digest 的本机批准，不再追加确认弹窗。

| 内容 | 建议默认方式 | 限制 |
| --- | --- | --- |
| 技能 | 从锁定的不可变对象复制实体文件到宿主项目发现目录 | 修改源库或退出栖集不会使已复制技能消失；升级另行生成计划 |
| 规则片段 | 在对应规则文件写受管块 | 普通 Markdown 跳转链接不能视为宿主会自动加载正文 |
| MCP 服务 | 按宿主格式写受管配置节点 | 只存凭据引用；写配置、进程可用、会话可调用分别验证 |
| 预设或纯组合框架 | 展开为确定的 Skill、规则、MCP、Plugin revision | 不把组合整体伪装成单个软链；展示各组件及其管理归属 |
| 有安装动作的框架或插件 | 使用已验证的宿主适配器生成生命周期计划 | 不通过复制技能目录宣称框架安装完成；未知安装器先不执行 |

软链接作为默认安装选项，只指向管理器固定版本 store，备份、回滚及指纹复核与复制共用事务；文件已写入不等于宿主已经加载。不得指向可变的来源工作目录。锁定内容不能原地改写；升级须切到新对象。链接依赖本机路径，不能宣称复制仓库即可在另一台机器使用；锁文件应支持重新物化。store 清理前须核对所有项目引用、恢复记录和待执行计划，不能制造断链。

“跳转”分两种：界面上的打开来源仅用于查看；宿主提供的 include/import 才可能加载内容。后者需要逐宿主验证相对路径、加载范围、权限和嵌套规则，未验证前使用受管块内联。

存储沿用现有边界：

- 共享仓保存来源、固定 revision、manifest、内容对象与预设。
- 项目只保存所选宿主的技能、规则和配置，不添加管理器专用清单、锁或隐藏目录。
- 应用数据目录 `~/.perch/` 保存安装选择、版本记录、本机路径、ownership 证据、接入基线、计划、journal 和备份。项目记录按 canonical realpath 的 SHA-256 隔离，不提交到用户 Git 仓库或上传云端。
- 用户级配置只在明确选择该作用域时生成独立计划；项目勾选不默认改变全局配置。

## 4. 可还原机制

在第一次实际接管或写入某个对象前，保存该对象的接入基线。仅打开项目不建立写入基线。基线需要区分不存在、空文件、普通文件、目录与链接，并保存内容、适用的权限/可执行位、链接原始文本及归属证据。不承诺恢复所有文件系统扩展属性；有额外元数据要求时须先补充格式与验收。

每次 operation 另存操作前后的状态、内容指纹、逐步 journal 和恢复依赖。复制件的基线与链接节点的基线分别处理，绝不通过恢复链接去改外部目标。基线和备份保存期限须在清理前明确；缺失恢复材料时不能显示“可完整还原”。

| 用户动作 | 目标状态 | 处理边界 |
| --- | --- | --- |
| 取消启用 | 从项目期望中移除能力，并规划移除未漂移的受管入口或规则 | 保留项目原有项；若仍由用户级配置继承，显示仍可用 |
| 撤销一次操作 | 恢复该次 operation 前的受管状态 | 先校验后续修改和操作依赖；有依赖则阻塞或明确规划逆序撤销 |
| 恢复接入前状态 | 按对象基线撤销栖集接管以来的修改 | 恢复原有内容或链接，移除栖集新增内容；保留之后的用户编辑并列出冲突 |
| 停止管理，保留当前文件 | 保持当前能力落地结果，注销管理绑定 | 清楚说明技能仍可能可用；共享 manifest/锁是否移除单独预览，不销毁历史备份 |
| 插件停用或卸载 | 通过宿主命令改变插件状态 | 另行生成计划；不能用文件备份宣称撤销插件已经执行的外部副作用 |

恢复前先检查整项计划的目标、当前指纹、备份完整性和依赖，尽早呈现全部已知冲突。执行仍需逐步复核；预检不能代替跨进程锁或防止后续竞争，也不构成跨文件原子保证。

漂移处理使用“基线 / 栖集最后写入 / 当前内容”判断。当前内容仍等于最后写入时可按计划恢复；已经改变时保留现状并给出差异。规则块外的新增内容应保留；无法证明可安全合并时只生成合并草稿，禁止整文件覆盖。当前 Alpha 的整文件 hash rollback 不具备此合并能力。

失败或进程中断时，记录已完成、未执行和有冲突的步骤；恢复 journal 可续办，界面显示“部分恢复”，直到逐项回读完成。不要只以备份存在或进程退出码作为恢复成功依据。

## 5. 界面流程提案

项目页现采用上下结构：顶部为紧凑项目选择区，下面与全局配置复用同一资源草稿，支持技能、AGENTS 片段、MCP 和插件标签。项目选择不复制或部署其他项目草稿，按工具预览只提交该工具的选择。“项目技能现状”、继承信息和待批准计划移入“项目详情…”，读取错误仍直接展示。后续恢复流程目标为：

1. **项目现状**：首次打开显示盘点摘要；已有、受管、继承与未知分别可查。
2. **整合选择**：默认保留已有配置；明确展示冲突、接管范围和框架展开项。
3. **变更预览**：逐项展示目标宿主、作用域、路径、落地方式、增改删、管理归属变化及可恢复范围，再进入现有批准 sheet。
4. **操作历史**：查看写入和验证结果，分别提供“撤销此次操作”“恢复接入前状态”“停止管理，保留文件”。

勾选状态只表达期望；“项目已有”“用户级继承”“文件已写入”“宿主验证待完成”独立显示。取消草稿或关闭预览不得修改项目。不能用一个“还原”按钮隐藏不同动作的范围。

## 6. 实施顺序与验收

本提案挂靠现有 M1–M4，不新增已交付承诺：

1. M1：已补齐本机 ownership 判断、未受管同路径冲突和取消选择后的移除计划；旧配置明确接管仍待实现。
2. M1/M2：恢复预检、journal 逐步恢复和项目技能现状已实现；首次接入基线、完整恢复/退出计划和操作历史界面仍待实现。
3. M3：按 Codex / Claude Code 实际版本补规则加载链、继承观察与宿主验证；在此之前只报告配置事实。
4. M4：三方合并与框架依赖求解。软链接模式须单独通过宿主和恢复验收后开放。

| 场景 | 必须观察到 |
| --- | --- |
| 打开带规则和技能的项目后取消 | 项目文件逐字节不变，没有新增 manifest 或发现入口 |
| 已有技能恰好与 catalog 同内容 | 显示已有；没有明确接管时不获得删除或升级权限 |
| 选择同名不同内容的技能 | 写入前阻塞；原目录、权限与外部链接目标不变 |
| 追加规则，随后取消启用 | 只移除本次受管内容；原有正文和后加的块外正文保留 |
| 取消已受管技能，用户级仍有该技能 | 受管项目入口移除，锁同步；仍显示继承可用 |
| 接管前分别为不存在、空文件或软链接 | 恢复后保持各自原始类型；空文件不能误作原本不存在 |
| apply 后用户修改技能或规则，再要求恢复 | 明确列出冲突，不覆盖新编辑；不误报全部完成 |
| 连续应用 A、B 后撤销 A | 识别对 B 的依赖，阻塞或生成可审阅的逆序计划 |
| 第 N 步恢复时中断，再次打开 | journal 显示实际完成项，可继续处理；不会重复覆盖已恢复内容 |
| 另一进程在预检后改文件 | 执行时再次校验并报告冲突，不使用旧观察覆盖 |
| 缺失本机基线或备份 | 说明可重新物化的版本与不能恢复的历史范围 |
| 退出应用、来源目录消失或离线 | 实体复制的已部署技能仍可读；完整对象可用于重新物化 |
| 框架包含插件安装或 hooks | 展示执行组件和恢复限制；不把文件还原等同于副作用撤销 |

实现测试使用临时项目、隔离 state 和假宿主，不更改真实全局配置。断言输出内容、类型、权限、残留、冲突与恢复状态；不以常量、自我镜像或仅检查调用次数替代行为验证。

## 安装包离线资源

安装包携带 `SkillSetLibrary` 快照（目录索引、技能内容、预设、规则与离线对象）。应用和配套 CLI 脱离源码仓库后，将随包快照按内容版本复制到本机状态目录 `bundled-libraries/<revision>`，再生成部署计划；对象写入不修改已签名的应用资源。显式配置的仓库仍优先使用。打包验证必须在仓库外使用隔离 state，验证未批准零项目写入、批准后技能正文与规则写入、离线对象核验，不能只以 MCP 握手成功作为部署可用的依据。
