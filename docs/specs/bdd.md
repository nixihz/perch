# BDD 场景与执行约定

状态：五个纵向切片已实现（2026-10-22）。当前覆盖项目部署审批、计划漂移、阻塞 Skill，来源预览的远端失败、固定 commit 和隔离不收录，MCP 配置的凭据拒绝与脱敏、环境变量名称校验和未知字段保留，Plugin 生命周期的风险确认、状态漂移和审批前零宿主进程调用，以及原生 UI 的首开任务引导、键盘导航、展开标题与空白点击、搜索空态、权限失败说明、项目空态、MCP/Plugin 表单、计划 sheet 和双层审批取消。

## 1. 目标与边界

BDD 用产品行为描述高风险规则。项目部署与 Plugin 生命周期调用与 App、CLI、MCP 相同的 `SkillSetService`；来源预览调用共享的 `SourcePreviewService`。场景验证真实临时项目、Git checkout、计划状态、文件、锁、宿主命令调用日志和错误码，不复制核心实现，也不为测试增加产品分支。

### 用户打开应用后怎样完成任务

用户的主要目标是为一个本机项目配置 AI 工具的技能和规则。侧栏按这个任务组织：「项目配置」放置项目与预设；「技能与规则」放置技能库、规则片段与技能来源；「AI 工具」放置 MCP 服务、插件与 AI 接入。项目是入口，预设是加快选择的方式；用户无需先理解来源记录、管理归属或规则文件标记。

| 用户当前的问题 | 操作路径 | 应观察到的结果与边界 |
| --- | --- | --- |
| 第一次打开，能做什么？ | 阅读项目页的三步说明，选择本机目录；也可先浏览技能库或查看预设 | 空态给出可执行的入口。浏览和切换页面不生成计划、不写项目 |
| 想快速给项目配一套常用能力 | 项目 → 使用预设，或预设 → 用于项目 → 核对差异 → 载入项目草稿 | 载入只修改应用内草稿，保留 AI 工具选择；取消不改变草稿与项目 |
| 想先确认一个技能的内容 | 浏览技能库 → 阅读正文 → 按需展开详细信息 | 正文优先。点击展开标题文字与空白区域都能展开或收起，来源和内容指纹按需可见 |
| 已选好技能，接下来怎么生效？ | 项目草稿 → 预览变更 → 审阅目标与变更 → 本机批准 → 再次确认写入 | 草稿、计划和写入是三个独立状态。退出审阅和取消确认均不写项目 |
| 想配置连接或插件 | MCP 服务或插件 → 生成对应计划 → 核对宿主、范围和风险 → 本机批准 | 生成项目技能计划不替代 MCP 或插件的独立审批；文件写入与宿主已加载分开描述 |

首开与导航场景必须从真实原生窗口操作入口，验证到达的任务页面及只读边界；仅检查菜单数组、按钮文案或视图内部状态不能证明用户能够完成这条路径。展开场景须分别发送真实鼠标点击到标题文字与右侧空白，由 WindowServer 按全局坐标路由，并等待原生展开状态改变，再验证内容出现或隐藏；不能只调用箭头的可访问性动作，也不能在发送事件后直接报告成功。已有服务级场景继续证明审批、事务与失败规则，避免为导航优化重复审批通过的服务测试。

项目部署功能文件是 `tests/SkillSetBDDTests/Features/ProjectDeployment.feature`，对应以下验收规则：

| 场景 | 验收映射 |
| --- | --- |
| 未批准的部署计划不会写入项目 | S5 的核心审批边界；MCP/CLI 协议层另测 |
| 用户批准精确计划后写入项目 | S5 的核心审批与写入链路 |
| 计划生成后项目被修改时拒绝覆盖 | TX-02、TX-05 |
| 阻塞 Skill 不能进入部署计划 | INV-02 |

来源预览功能文件是 `tests/SkillSetBDDTests/Features/SourcePreview.feature`，对应以下验收规则：

| 场景 | 验收映射 |
| --- | --- |
| 远端失败不会留下预览 | SRC-01 的失败边界；失败后不保存记录，也不残留隔离目录 |
| 预览固定到所选 commit | SRC-01、VER-02；生成记录绑定解析后的 commit，标签移动后已保存预览仍读取原内容 |
| 预览只写入隔离区而不收录 | SRC-01；预览保存到隔离数据，不改变 catalog、库存或项目目录 |

来源预览场景通过真实本地 bare Git 仓库和 Git `insteadOf` 传输映射执行完整 clone、fetch、checkout 链路，不替换被测服务。远端失败也走真实 Git 命令，而不是注入异常。

MCP 配置功能文件是 `tests/SkillSetBDDTests/Features/MCPConfiguration.feature`，对应以下验收规则：

| 场景 | 验收映射 |
| --- | --- |
| 带凭据的 MCP URL 不生成配置计划 | MCP-02、MCP-05；草稿错误发生在计划创建前，项目配置不变 |
| 凭据值不能伪装成环境变量名称 | MCP-02、MCP-05；拒绝在 env 名称位置携带值，错误信息不回显凭据 |
| 非法环境变量名称不生成配置计划 | MCP-02、MCP-05；env 只接受变量名，不接收值或空格 |
| 批准后写入 MCP 配置并保留未知字段 | MCP-03、MCP-05；批准后写入受管 server，保留外部顶层键和已有 server 的未知字段 |

MCP 场景通过 `SkillSetService.makeMCPConfigPlan`、计划存储和文件事务执行，使用项目级 Claude `.mcp.json` 临时 fixture，不读取或写入真实用户宿主配置。

Plugin 生命周期功能文件是 `tests/SkillSetBDDTests/Features/PluginLifecycle.feature`，对应以下验收规则：

| 场景 | 验收映射 |
| --- | --- |
| 未确认可执行组件风险时不生成安装计划 | PLG-03；风险确认在计划创建前完成，失败后零计划、零宿主进程调用 |
| 已批准的计划在 Plugin 状态变化后拒绝执行 | PLG-02；重新读取安装事实发现状态漂移，计划不标记已应用，零宿主进程和零 operation |
| 审批前不调用宿主进程 | PLG-01；待批准计划不能执行，宿主命令调用与 operation 都为零 |

Plugin 场景使用隔离的临时 `HOME`、Claude Plugin 缓存、安装索引和启用设置，并把宿主 CLI 指向临时可执行脚本。脚本只在被调用时追加参数到日志；场景据此验证真实 `Process` 边界没有被触发，不通过 mock 调用次数替代产品结果。

原生 UI 功能文件是 `tests/SkillSetBDDTests/Features/NativeUI.feature`，对应以下验收规则：

| 场景 | 验收映射 |
| --- | --- |
| 侧栏和快捷键可用键盘操作 | UI-01；方向键从项目进入相邻预设，`⌘2` 与 `⌘3` 保持原目的地，搜索字段暴露原生提示文本 |
| 首次打开可以按任务浏览技能和预设 | UI-02；三步引导和项目空态分别提供添加、浏览技能库与查看预设入口；入口真实切换页面，零项目登记、零计划 |
| 点击技能详情标题和空白展开或收起不会改写项目 | UI-01、UI-02；实际鼠标点击文字与右侧空白分别展开、收起来源和指纹，返回项目后草稿入口仍可用，项目目录与 sentinel 文件不变且零计划 |
| 原生计划 sheet 展示完整审批信息 | UI-01；sheet 显示目标路径、完整 digest、状态、批准前须知、第一项变更和审批按钮 |
| 按 Escape 取消计划不改变项目和计划状态 | UI-01；sheet 关闭后焦点回到侧栏，计划仍待批准且 digest 不变，项目目录不变 |
| 搜索无结果时不再显示旧 Skill 详情 | UI-02；搜索筛选后清除失效选择，显示零匹配和清空搜索的下一步 |
| 项目权限失败时解释状态和恢复入口 | UI-02；真实不可读目录触发观察失败，显示具体原因和重新选择项目的恢复提示，不生成计划 |
| MCP 表单拒绝凭据值且不生成计划 | MCP-02、UI-02；原生表单拒绝 env 名称位置的值，校验文本不回显凭据，零配置计划 |
| Plugin 风险确认门解锁安装计划 | PLG-03、UI-01；风险未确认时安装按钮禁用，勾选后可生成计划，宿主进程仍为零调用 |
| 批准部署前需要第二次确认 | UI-01；首次批准只打开确认对话框，显示路径、变更数量和两个选择；取消后计划仍待批准且项目不变 |

原生 UI 场景通过 LaunchServices 启动临时 `.app`，让当前构建的 `SkillSetDesktop` 能成为前台应用并接收真实鼠标点击；直接运行未打包二进制会得到禁止激活的策略。临时包复用构建输出中的资源与框架，使用独立应用标识，显式传入隔离的 `HOME`、`CFFIXED_USER_HOME`、`CODEX_HOME` 和应用数据路径，结束后按实际启动 PID 终止并清理临时目录。

场景通过 macOS accessibility tree 查找窗口、source-list、表单字段、复选框、sheet、静态文本和按钮，并发送文本、方向键、`⌘2`、`⌘3`、Escape 与鼠标点击。侧栏操作从实际 AX 行读取视觉顺序，不在测试中复制导航数组；展开测试识别原生 disclosure 的标签与边界，必要时通过原生滚动条或控件已公开的滚动动作显示右侧详情，再定位文字与空白发送鼠标事件，不要求展开标题必须是独立静态文本。Plugin 场景在隔离 `HOME` 中创建真实缓存 manifest，并把宿主 CLI 指向只记录调用的临时脚本。场景同时回读隔离 Application Support 中的项目登记与计划记录，以及真实临时项目目录，不读取或改写真实宿主状态。

所有场景只使用隔离的临时 Application Support、项目目录和宿主 HOME。测试不得读取或写入真实的 Codex、Claude Code、Keychain、全局 Skill 或宿主配置。

## 2. 文件结构

```text
tests/SkillSetBDDTests/
  Features/                     中文 Gherkin，CucumberSwift 只递归读取此目录
  BDDWorld.swift                场景状态、临时工作区与可观察断言
  NativeUIHarness.swift         原生子进程、Accessibility 与键盘操作
  ProjectDeploymentSteps.swift  唯一的 StepImplementation 与步骤定义
```

SwiftPM 会把所有测试目标链接进同一测试包，因此整个 package 只能有一个 `extension Cucumber: StepImplementation`。新增功能文件时复用同一入口，并在 `setupSteps()` 中注册步骤。

## 3. 写作规则

- 使用 `# language: zh-CN`，功能、场景和步骤描述业务结果，不描述按钮坐标或内部函数名。
- `假设 / 当 / 那么` 保持因果顺序；一个场景验证一条可观察规则，失败路径单独成场景。
- 步骤只通过共享服务、真实临时文件和公开只读状态断言结果；禁止同义反复断言，禁止复制实现公式生成期望值。
- 文件名、Skill ID、错误码和受管块 ID 保持字面值；中文说明使用项目现行术语。
- Gherkin 行内 `#` 会被解析为注释，即使位于引号内。需要多行或含 `#` 的正文时使用 DocString，不要拼进普通步骤。
- 场景数据不得包含真实凭据、用户路径或个人配置快照。

## 4. 运行方式

```bash
task bdd
# 等价于
CUCUMBER_TAGS=bdd CUCUMBER_VERBOSE=1 swift test
```

执行限制：

- 不要使用 `swift test --parallel`。Cucumber 场景不在 `swift test list` 中，并行执行会漏跑且可能仍通过。
- 不要用 `swift test --filter <场景名>` 选择场景。该命令不会运行动态生成的场景，可能报告零测试通过。
- 不使用 `--skip` 缩小 BDD 的测试范围，XCTest 的选择清单同样可能遗漏动态场景。按标签运行后，核对日志确实包含目标场景的步骤；其他测试通过不代表该场景已执行。
- 使用标签筛选：在功能或场景前添加 `@bdd`，再设置 `CUCUMBER_TAGS=bdd`。
- 展开标题与空白点击场景另有 `@disclosuretargets` 标签，可用 `CUCUMBER_TAGS=disclosuretargets swift test` 定向执行真实鼠标交互。
- 常规 `swift test` 同时执行 Swift Testing、XCTest 布局回归与 Cucumber 场景，CI 沿用该入口。
- 原生 UI 场景需要交互式 macOS 桌面会话与 Accessibility 权限。`CI=true` 或测试进程未获授权时，场景以 `XCTSkip` 明确跳过；本机运行 `task bdd` 时仍会执行这些场景。

## 5. 当前边界

原生 UI 已覆盖首开任务入口、导航、展开交互、搜索与项目空态、权限失败、MCP/Plugin 表单和双层审批取消。它不替代文件事务、Plugin 状态漂移和宿主命令边界的服务级场景，也不证明真实宿主已加载配置；这些边界继续由现有服务级 BDD 单独验证。

## AGENTS 片段原生闭环

`TemplateWorkflowUITests` 从独立原生进程通过 AX 新建片段、输入多行正文、选择项目、用 Escape 取消、查看差异、二次批准，最终回读临时 AGENTS.md 并验证手写正文保留。目标选择取消需保持草稿字节不变，审批取消需保持目标文件不变。系统允许窗口截图时保存目标选择、规则差异和写入结果到 `/tmp/perch-template-{target,diff,result}.png`。`TemplateEditorTests` 另以原生 NSHostingController 在明暗外观捕获 `/tmp/perch-template-{target,diff}-{light,dark}.png` 并检查弹窗尺寸；Accessibility 不可用时端到端场景明确跳过，不宣称界面通过。`TemplateWorkflowTests` 补充双宿主项目／全局、更新与取消启用、旧预览、引用损坏和外部文件修改的行为验证。

AXPress 会绕过鼠标手势识别，因此上述端到端通过不能单独证明鼠标可点击。`ButtonInteractionTests` 在测试窗口向三种实际 `AppButtonStyle` 发送鼠标按下、松开事件，验证启用时执行一次、禁用时不执行；事件只发给测试窗口，不注入系统鼠标。曾有零距离拖拽用于按压缩放，导致 AXPress 有效而鼠标点击零执行，该测试在移除手势前失败、移除后通过。按钮反馈必须使用原生 `configuration.isPressed`，不得以额外手势接管点击。

用户库不预置片段或预设。`UserLibraryTests` 验证正常首开空库、旧同标识的用户编辑保留、删除重启不恢复、删除预设不改变已载入草稿；`TemplateEditorTests` 验证被引用片段仍可删除、项目文件保持原样，失效引用在计划边界被拒绝，清理后可重新预览。引用和使用位置盘点失败不再锁定库条目的删除。
