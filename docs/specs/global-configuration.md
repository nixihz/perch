# 全局配置、原始数据与还原

状态：用户作用域技能与规则、原始备份、撤销与退出管理已实现。真实宿主会话加载、跨进程锁及完整故障注入仍待验收。

## 入口与作用域

侧栏「配置 → 全局配置」与项目并列，快捷键为 `⌘9`；项目仍是默认入口。全局页选择 Codex 或 Claude Code，独立保存草稿，预览并批准后才写资源目录。技能库的收录、编辑和来源同步均不代表全局启用。

Codex 技能使用 `~/.agents/skills`，规则使用 `CODEX_HOME/AGENTS.md`（默认 `~/.codex/AGENTS.md`）。Claude 技能使用 `CLAUDE_CONFIG_DIR/skills`，规则使用 `CLAUDE_CONFIG_DIR/CLAUDE.md`（默认目录为 `~/.claude`）。路径从当前宿主配置解析，在全局页和计划中展示真实绝对路径。

技能根目录可以是指向现有目录的软链接，包括 HOME 之外的目录。扫描、计划、归属与还原使用解析后的真实路径，保留原目录软链接；计划摘要绑定真实技能根目录，执行前重新解析宿主入口，目标发生变化时拒绝旧计划。此支持只适用于技能根目录，根目录内的外部技能软链接及规则文件软链接仍沿用原有保护。

MCP 和插件继续使用现有管理页及各自的用户作用域计划；全局技能的文件还原不撤销插件脚本产生的外部副作用。项目页展示所选宿主用户目录内的技能与规则文件，不推断祖先目录、插件、同名覆盖优先级或当前会话加载结果。

## 本机状态与原始数据

本机状态目录默认为 `~/.perch`，可由 `SkillSetRuntimePaths` 显式替换：

```text
global/<host>-draft.json       用户选择，尚未部署
global/<host>.json             实际部署期望、修订与逐路径归属
global-baselines/<uuid>/       首次接管的原始技能完整包
plans/                        待批准和已执行计划
staging/                      固定计划载荷，也用于规则撤销比较
operations/<uuid>/             journal 与每次操作前的备份
```

不将 HOME 登记为项目，不在 HOME 写 `skillset.json` 或项目锁。已有相同内容默认保持原归属，已有不同内容默认冲突；用户显式选择接管后才保留原包并写入，后续版本更新不替换首次接管基线。规则保存原始文件与基于原始块外内容生成的规则参照，避免更新前已有的块外编辑在还原时丢失。

管理状态不能单独授予删除权：必须有本机完成的文件事务，其状态文件写后指纹与当前状态一致。管理记录损坏、缺少凭证或存在未恢复事务时停止普通部署。

## 三种还原操作

| 操作 | 行为 |
| --- | --- |
| 撤销此次操作 | 根据该次 journal 与备份生成反向计划；有后续管理状态变化时先撤销后续操作 |
| 恢复接管前状态 | 恢复原始技能包；移除栖集新增技能；规则恢复原始块，保留后续块外编辑；清空管理选择 |
| 停止管理，保留文件 | 只清空本机管理归属和选择，保留当前文件与用户编辑 |

三项操作复用同一份计划、有效期、人工审批、旧指纹复核、备份及逐项 journal。撤销停止管理时也复核将重新接管的文件，不借此自动取得用户编辑后的内容归属。恢复后保存空管理修订供审计和撤销，历史包与备份不自动清理。

原来不存在的规则文件可以还原为不存在，原来为空的文件仍为空文件。规则块外新增的内容在部署、更新、还原及撤销时保留；规则块内或技能包的用户修改会阻止覆盖或还原。原始备份缺失或改变时不猜测内容。规则撤销需要该操作的 staging 参照；参照缺失时明确报错，不能静默退化为整文件覆盖。

## 执行边界与验证

全局计划由 `SkillSetService` 执行。事务根取资源与本机状态的共同祖先以复用文件事务；该根不授予任意写权限，执行前仅允许所选宿主的单个技能目录、规则文件和对应全局状态文件，重新核验 digest、路径与软链。宿主支持的固定版本技能链接沿用版本库适配器，其他外部软链不自动覆盖。

文件事务失败会尝试恢复已写步骤，逐项持久化结果；未恢复事务保留历史状态并阻止新部署，启动时由既有恢复机制续办。当前不承诺跨文件原子性或跨进程互斥。

验证使用隔离 HOME、宿主目录和本机状态，覆盖两宿主审批前零写入、完整包部署、未受管邻居与原件保留、首次接管、连续更新、撤销、退出管理、空文件、规则块外编辑、备份缺失、陈旧计划与软链置换。原生界面测试覆盖最小窗口的明暗外观、草稿持久化、取消计划、批准与还原；不修改用户真实全局资源。
